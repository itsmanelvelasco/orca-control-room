# Docs: update by reinstalling @main, and unload dev copies after testing

## summary
The install and update steps now work: install or move to the latest with `orca plugin install https://github.com/itsmanelvelasco/orca-control-room.git --ref main` (+ `--approve`). Developers unload a dev folder when they are done testing.

## entry
- README Install and CLAUDE.md Deploy: an install is pinned to one commit; with no `vX.Y.Z` tags, `orca plugin update` never moves it. Run the install command again, with the `--approve` Orca prints when asked.
- README Develop and CLAUDE.md Commands: every dev folder gets the key `local.control-room`; several loaded folders clash and a stale one can show a blank panel. `orca plugin dev unload .` after testing.
- The `owner/repo@main` form failed on Windows (Git `Permission denied`, then `EBUSY` on a locked temp folder); a `https://...@main` URL is read as a repo name. The `.git` URL with `--ref main` worked. A retry helps on `EBUSY`.
- Found when an installed copy stayed on d52d11c and three old worktrees were loaded as dev copies. No tags created.

# The worker keeps the funnel current

## summary
The worker now builds the funnel and answers `funnel.snapshot`, so the Funnel tab (slices 3-5) can draw it. It reuses what the Waits view reads, and reads closed items and bot work only while the tab is visible.

## entry
- `src/views/funnel/refresh.ts`, `worker.ts`: build from the Waits loops' data; read closed items (`bot item list --all`) and `bot work list` per bot every 20 s while a panel asks; loading until that read ran once; rebuild at once on a Waits pass or agent event while watched; last good rows per bot on failure, one note per source.
- The funnel never queues in front of Waits: an identical call shares the one running (the runner merges by argv); a timeout stops a funnel source for the turn.
- R8 AC now: 0 extra calls while the tab is hidden; while visible, 2 calls per bot every 20 s (9 bots: about 1 call a second, one read about 16 s).

# One Control Room panel, a read-only grep test and a README for the store

## summary
The three panels are now one Control Room panel with three tabs: Waits, Shipping line, Agents. A test fails the build on any write, and the README explains install and the read-only rules.

## entry
- `src/views/room/*`: one panel, tabs over the slice 2-4 views; only the tab shown polls; Orca remembers the last tab (`persist: 'plugin'`; `'storage'` raced in tests). The Waits tab shows its count. The manifest change needs a new approval.
- `test/readonly.test.ts` (R8): every file in `src` is checked for CLI commands off the allow-list, terminal writes or sends, host calls that do not read, open or focus, `settings.set` and network calls; the manifest asks for the six PRD capabilities and no hooks.
- README in English; screenshots from `src/views/room/panel.check.ts`. `orca plugin shot --scenario` captured Orca's own sidebar for every light shot and for the Waits tab, so only the dark Shipping line and Agents pictures are in.
- Live on Windows: the worker uses 0.41% of one core at rest.
- `worktree ps` (agent states and trust reasons) runs in its own 4 s loop, apart from the slower item, gate, bot and Run reads. Live on Windows, with Regia running: a Claude Code trust prompt gets its "trust this folder" label 3.5-5.8 s after the agent starts to wait (4 runs; it was 16-28 s). `test/waits-slow.test.ts` checks it with every other CLI call at 2.5 s.
- Relative times are English whatever Orca's locale ("24s ago", not "hace 24 s"): `src/views/time.ts` replaces Orca's locale-following `RelativeTime`.
- Hidden tabs ask nothing, not even at mount, and Tabs is controlled by the tab that polls. The Waits heading no longer repeats the count on its tab. The read-only grep also catches network modules without `node:`, `require`, `import()`, and indirect host calls.
